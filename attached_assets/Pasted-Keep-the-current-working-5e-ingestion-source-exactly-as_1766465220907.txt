Keep the current working 5e ingestion/source exactly as-is. Do not remove or refactor existing logic except where needed to support importing additional sources. Add new optional import modules for additional sources/editions and merge them into the existing Postgres dataset.

Goals

Preserve existing functionality and data source.

Add additional sources listed below and import them into the same Postgres DB.

Merge duplicates safely (upsert / de-dupe) so we don’t create double entries.

Preserve provenance: every record should track where it came from.

Database / Data Model Requirements

Use the existing tables if already present. If missing fields, add columns rather than creating a new incompatible schema.

Minimum normalized fields per item:

name (text)

edition (text enum-ish: odnd, adnd, 3e, 4e, 5e, 2024/onednd)

type (text: weapon/armor/potion/ring/wondrous/etc.)

rarity (text: common/uncommon/rare/very_rare/legendary/artifact/unknown)

source (text)

source_url (text)

rules_text (text nullable)

is_homebrew (bool)

optional: tags (text[] or join table)

Duplicate Merge Rules (IMPORTANT)

When importing an item, attempt to find an existing match using this priority:

Strong match: canonical_name + edition + type

If type missing, match on canonical_name + edition

If edition missing in incoming data, do NOT merge automatically (insert as new with edition = 'unknown' or skip)

Where:

canonical_name = lowercased name, stripped punctuation/extra spaces (create helper function)

On Merge / Upsert Behavior

Keep the existing record as “primary”.

Fill in missing fields from the new source if existing is null/unknown.

Never overwrite existing non-null fields with null/unknown.

Always append provenance: if a new source provides the item, add a row in item_sources or append to a sources JSON/array field.

If both have rules_text, prefer the existing one unless it is empty; otherwise keep both in provenance (don’t lose text).

Recommended structure:

items table = canonical item

item_sources table = one-to-many sources per item:

item_id, source_name, source_url, source_item_id (optional), imported_at

Import Strategy

Add imports as separate scripts/modules so each can be run independently:

import_5e_extra_sources

import_3e_sources

import_4e_sources

import_adnd_sources

import_odnd_sources

Each importer should:

Fetch data (clone GitHub repo or scrape HTML)

Parse into normalized item objects

Upsert into Postgres using the merge rules above

Record provenance in item_sources

Safety / Practical Notes

Some editions won’t have rarity; set rarity='unknown'.

If a source is hard to parse for full rules text, import at least name/type/edition/source/source_url so it still works for card draws.

Keep all new imports optional behind feature flags or CLI commands so production behavior doesn’t break.
